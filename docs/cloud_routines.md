# Scheduled runs in the cloud (owner 2026-11-01; live 2026-11-02)

The twice-monthly chain and the quarterly search-interest refresh run as cloud routines at https://claude.ai/code/routines. They are **enabled** and the local scheduled tasks were deleted by the owner on 2026-11-02, so these are the only copies (a local and a cloud run on the same day would open two tournament PRs). A cloud run starts from a clean clone, so it has no raw data, no built-in browser, no `.env` and no local `gh` login.

A dead-man's switch (`.github/workflows/refresh-watchdog.yml`) fails on the 2nd and 16th if no "Tournaments" PR was opened.

**Raw data.** The gitignored `data/raw` CSVs live gzipped in the private repo `abov/courtconnect-data` (`raw/`; `overture_addresses.csv.gz` is split in `.partNN` chunks). Each routine has it as a second git source; `python ingestion/cloud_bootstrap.py` unpacks it into `data/raw`, installs `requirements.txt` and builds `courtconnect.duckdb`. After a local extract + load, refresh the data repo: gzip each file in `data/raw`, `split -b 80M -d overture_addresses.csv.gz overture_addresses.csv.gz.part`, commit, push.

**Never export from incomplete raw data (2026-11-15).** A cloud run built from the stale data repo and committed a `venues.json` with 8,300 fewer venues (AZ/NM/HI/TX/MX nearly empty). Before committing an export, run `python ci/check_venue_drop.py`: it fails when the total or any region of 50+ venues falls more than 10% against `origin/main` (CI and the pre-push hook run it too; a real removal needs `ALLOW_VENUE_DROP=1` and a reason in the PR). If it fails, do not commit `venues.json`: the raw CSVs for a region are missing, so refresh `abov/courtconnect-data` first.


**dbt packages in the sandbox (2026-11-15).** Plain `dbt deps` fails there with "not a gzip file": it downloads `codeload.github.com/<owner>/<repo>/tar.gz/<version>`, and the egress proxy answers that with a 403 JSON body ("GitHub access to this repository is not enabled for this session") for any repo not attached to the session, which dbt then fails to gunzip. `hub.getdbt.com` and its CDN `public.cdn.getdbt.com` ARE reachable (TLS verified, no allowlist change needed). `cloud_bootstrap.py` now runs `dbt deps` twice, then falls back to downloading the versions pinned in `transform/package-lock.yml` (elementary, dbt_utils) from the hub CDN, checking each sha1 and unpacking into `transform/dbt_packages`; `fresh_db.py` skips its own `dbt deps` once `dbt_packages/elementary` exists. Keep `package-lock.yml` committed: it is what the fallback reads. Alternative: attach dbt-labs/dbt-utils and elementary-data/dbt-data-reliability to the routine, or allow `codeload.github.com`, so plain `dbt deps` works.

**Verified 2026-11-16 (fresh sandbox, data repo attached, `main` at b80293f):** `cloud_bootstrap.py` falls back to the hub CDN for the dbt packages and `dbt build` is green: PASS=475, ERROR=0, WARN=1 (`assert_mx_pins_have_subregion`, a warn-only test, ~1,000 Mexican pins). On 2026-11-15, before the data repo was refreshed, the build failed `relationships_place_sport_overrides_place_id` (59 rows) because `courtconnect-data` lacked the AZ/NM/HI/TX/MX extracts; that is fixed by keeping the data repo current: after every local extract + load, refresh `abov/courtconnect-data` (see Raw data above), otherwise seeds that reference newer places fail in the cloud. In the sandbox, Overture S3 reads need `AWS_ACCESS_KEY_ID`/`AWS_SECRET_ACCESS_KEY` unset (the proxy injects placeholders the public bucket rejects with 403); `overpass-api.de` is blocked, so OSM extracts cannot run there.

**What differs from local runs** (the routine prompts say so; the docs stay written for the local run): no browser pane (ITF, Club Locker, padelusa, Instagram, Google Trends and reddit.com are read with WebFetch once, otherwise listed as "needs browser, not read"); no `.env` (sports sheet sync, form reports, GoatCounter not checked); no extract; if `gh` is not authenticated a part pushes its branch and puts the PR text in the session note, and Part 5 stops at its preflight.

**To change a routine:** edit the steps in `docs/tournament_run_parts.md` / `docs/refresh_agent.md` on `main` (the prompts read them at run time); edit a routine's own prompt, cron or enabled flag only at claude.ai/code/routines. Run now on a part to retest it.
