# 0028. Five-state scope: California, Nevada, Washington, Oregon, Hawaii

Date: 2026-11-02. Status: proposed (owner 2026-11-02 asked for the expansion). Step 0 (generalize, below) was approved the same day and merged in #477. Oregon (the data layer: OSM courts and parents, Overture places and addresses, ZIPs, places, outline, bounds) started 2026-11-02 on branch `claude/oregon-step`; OSM relation 165476 and the `OR` box were checked against Overpass (border bounds match). Oregon seed research (city rec centers, chains, campuses, leads, events) is not done yet. The app copy still says California and Nevada until the name and labels PR. Extends ADR 0014 (CalNeva); it does not replace it, and 0014's rules carry over unchanged.

## Context
ADR 0014 made the covered area a list of regions. `ingestion/regions.json` already drives the extracts, the border clip, the Census place list and `ci/check_regions.py`, so most of the work for a new state is configuration plus the places still hardcoded to CA/NV (listed below). The name "CalNeva" no longer fits five states, and `courtconnect-ca` is wrong as a repo name (owner 2026-10-23 kept it for CA+NV; this decision reopens only the question, nothing is renamed here).

## Decision (proposed)
- **Scope:** add `WA`, `OR`, `HI` to `regions.json`. Same rules as 0014: public pages only (ADR 0005/0007), inferred data labelled, link out only, no partnership emails. One state per step, each ending in a merged PR and a live check, so a bad state never blocks the others.
- **Name:** recommend **CourtConnect West** (short, true for 5 states, still true if Arizona or Idaho join). Alternatives: "Pacific West" (Nevada is not Pacific), "West Coast + Hawaii" (Nevada again). The name appears in the app title, meta tags, About card, README, CLAUDE.md, Makefile help, coverage report, `exposures.yml`, `app/llms.txt`, the manifest, the share card and 3 app pages (23 files mention "CalNeva"); one labels-only PR, as in 0014 step 3. Historical text (ADRs, past status lines) stays.
- **Repo / Pages rename (owner decides):** keep `courtconnect-ca` until after the December beta, then rename once. GitHub redirects the old repo URL, but Pages does not redirect the old site URL, and GoatCounter, share links and the beta would break. Recommended: keep the URL through the beta, rename in the first quiet week after it, with the old Pages site left as a one-page redirect.
- **Order (cheapest first):** step 0 generalize (no new data, CA/NV output must be byte-identical), then **OR**, then **WA**, then **HI**. OR first: one landmass, no new technical risk, and its border with CA exercises the clip. WA second: larger (Seattle), shares the Columbia River border with OR. HI last: smallest data but the most special cases (islands, map view, ZIPs).

## Step 0: generalize (one PR, no new data, no extract)
Hardcoded CA/NV places found in the code, each to be driven from `regions.json` (or mirrored from it and checked in CI):
1. `transform/macros/region_code.sql`: `region_code` lists `'CA'`/`'NV'`; `outside_region_bbox` has two literal boxes. Plan: a `regions` var in `dbt_project.yml` (code + bbox) read by both macros, and `ci/check_regions.py` fails if it differs from `regions.json`.
2. `accepted_values` for `region` in `transform/models/schema.yml` (3 places, lines ~677, 851, 870), `assert_watch_events_valid.sql` (tests CA and NV boxes by hand), `assert_courts_inside_region`, `assert_manual_venues_inside_region`: use the same var.
3. `ingestion/extract_overture_places.py` and `extract_overture_addresses.py`: one literal box `-124.5..-114.0 / 32.5..42.1`. Replace with an OR of the per-region boxes from `regions.json` (a single covering box would also read Idaho, Montana and Canada). `oneoff/overture_scale_benchmark.py` copies the box; leave it (sibling benchmark session).
4. `ingestion/load_raw.py` appends `*_nv.csv` only; `Makefile extract` lists NV by hand. Make load glob `_??.csv` (any state code) and let `make extract` loop over the regions; the courts/parents extractors default their output to `<stem>_<code>.csv` for any state after the first (`overpass.out_name`). (`extract_osm_walls.py --area metros` uses "california" because its tile list is California-only metros; that is correct, not a gap.) The cloud data repo holds `data/raw` as a folder, so the new per-state files ride along when it is refreshed.
5. `ingestion/extract_census_boundaries.py`: `STATEFP in ('06','32')`. Add a `fips` field to `regions.json` (06, 32, 53, 41, 15). `place_from_boundaries.py` and `build_places_lookup.py` already follow `REGIONS`.
6. `ingestion/ask.py` (rejects regions other than CA/NV, prompt text), `export_coverage_report.py` (Nevada-specific sentence), `export_app_data.py` docstring (`r` = CA/NV), `app/llms.txt` and `app/data-dictionary.md` (keep in sync).
7. App (`app/index.html`): initial and "reset" bounds `[[-124.6,32.4],[-114.0,42.2]]` (4 places); `zipPoint` accepts only 88900-96199 and says "outside California and Nevada"; "California only so far; Nevada coming next" fallback copy; ~15 text strings naming the two states; `data/calneva_outline.json` (state lines; its builder is not in the repo, only the file); `data/zips.json` (1,983 ZCTAs, also no builder in the repo). Plan: rebuild outline and ZIPs from Census files with a small script kept in `ingestion/` and listed in the runbook. **Hawaii:** one box for all five states is a useless first view (Hawaii is 2,500 miles out), so the default view is the mainland states and a "Hawaii" shortcut zooms to the islands; ZIP 967xx-968xx falls outside the current guard.
8. Hawaii in the extractors: the OSM state relation is a multipolygon of islands; `border()` already polygonizes outer ways, so it should work, but verify the relation id and that the tiles (3.5 x 5.6 degrees, mostly ocean) do not time out. NW Hawaiian Islands are excluded by the bbox. Oregon/Washington and Oregon/California boxes overlap at the border; `region_at` uses the polygon, as for Tahoe. Add test points to `ci/check_regions.py`: Portland vs Vancouver WA, Ashland OR vs Yreka CA, Honolulu, Hilo, Kahului, Seattle, Spokane, plus Boise/Vancouver BC as "none".
9. CI fixtures (`ci/fixtures`) hold no Nevada rows, so the NV path is untested in CI today. Add one row per new state (and one NV row) so the region tests mean something.
10. `search_metros.csv` / `int_search_interest.sql` (Trends, planning signal, not in the app): per-state queries are rescaled through Reno. Needs new metros (Seattle-Tacoma, Portland OR, Spokane, Eugene, Medford-Klamath Falls, Honolulu; check Google's codes) and a rescale rule per extra state. Lowest priority; do it after the data is live.

OSM border relation ids (from memory, **verify with Overpass before use**): WA 165479, OR 165476, HI 166563. Bboxes to propose: WA 45.5 / -124.9 / 49.05 / -116.9, OR 41.99 / -124.7 / 46.3 / -116.45, HI 18.85 / -160.3 / 22.35 / -154.75.

## Per-state step (same for OR, WA, HI)
Region config + test points, OSM courts + parents (`--area <state>`), Overture places + addresses, `load`, `build`, `reverse-geocode-blanks`, `city-boundaries`, a first look at the scorecard, `app-data`, PR. Scheduled routines (`docs/cloud_routines.md`, `docs/tournament_run_parts.md`, the refresh agent, the quarterly search-interest refresh) read their instructions from `origin/main`, so step 0's generic changes reach them on merge; their source lists and prompts name CA/NV, and each state's step extends them (tournament and event sources, discovery, search-interest geos and metros) only once that state's research exists, so no routine covers a state that has no data. After each state's extract, refresh the private raw-data repo. Then, as ADR 0014 step 5 did for Nevada: state seeds (parks and rec departments of the big cities, YMCA / Life Time / 24 Hour / university and military scans from `docs/gym_chain_scan.md` and `docs/public_facility_scan.md`, padel and pickleball leads, tournament and social sources in `docs/tournament_sources.md`), and the runbook rows. The seed research is the large cost; the extract is cheap.

## Cost and time (estimates, not measured)
- Extract: CA+NV takes about 15 min. By tile count the OSM extract adds roughly OR 4 min, WA 4 min, HI 2 min, plus parents and the Overture/address reads (about 1 min each, S3). The Overture release diff and the address extract scale with the boxes. A metro trial (`--area portland`) comes first and costs minutes.
- Venues: NV has 546 pins (about 170 per million people; CA about 250). Same ratio gives roughly OR 700-1,000, WA 1,300-1,900, HI 250-350. Raw size grows about 25%.
- Review work (per state): city rec centers, chains, campuses and leads are one session each, as for Nevada; about 8-12 small sessions per big state, 3-4 for Hawaii. Hawaii's quirks (many resorts with courts, military bases) follow the rules already set for Nevada (resorts: owner decides first).
- The 35-day freshness SLA and the twice-monthly runbook cover more area; the scheduled routines (tournaments, discovery, refresh agent, search interest) need their source lists extended per state, and the spend cap ($20/month, ADR 0019) is the limit to watch.
