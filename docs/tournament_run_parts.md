# Scheduled runs: five parts (owner 2026-10-24)

The single 1st/15th run (tournaments for every sport + data refresh) stopped after one source on 2026-10-24: too big for one session at the low-usage settings. It is now five scheduled tasks on consecutive days, all appending to ONE tournament PR per cycle, then the data refresh stacked on it. Each task prompt only says "read `docs/tournament_run_parts.md` from origin/main and do PART N"; the steps live here so they are versioned and reviewed.

| Part | Task id | Days (09:00 local) | Covers |
|------|---------|--------------------|--------|
| 1 | `courtconnect-tournament-refresh` | 1st, 15th | USTA SoCal/NorCal, USA Pickleball, PPA, ITF pro tour |
| 2 | `courtconnect-tournament-refresh-2` | 2nd, 16th | USA Badminton, R2 Sports, table tennis, Silicon Valley Open / US Squash, skyball, Club Locker squash |
| 3 | `courtconnect-tournament-refresh-3` | 3rd, 17th | USA Padel calendar, beach tennis organizers, padel rechecks and lead rechecks |
| 4 | `courtconnect-tournament-refresh-4` | 4th, 18th | Instagram sweep, new-venue social handles, player-group links |
| 5 | `courtconnect-data-refresh` | 5th, 19th | data refresh (`docs/refresh_agent.md`), stacked on the tournament PR |

Spend: each part is estimated at $1-1.50; the $5 weekly / $10 monthly caps of `docs/refresh_agent.md` count Part 5 only, ADR 0019's $20 a month is the ceiling for all five. If the month's total runs past it, drop Part 4 to the 1st of the month. The app must be open on those days (a missed run starts at the next launch).

## Rules for every part
Work in `C:\dev\courtconnect-ca` (Git Bash for commands; dbt is `.venv/Scripts/dbt ... --project-dir transform --profiles-dir transform`, there is no make). Read CLAUDE.md first and follow it (never read .env, no Google Places data, public pages only, no owner logins, honesty over polish). Cost rules: no subagents, no screenshots, no extended web search, read pages as text, narrowest check first. **Do the whole part: read every source listed for it. Do not stop early to save usage; if you truly cannot finish, list exactly which sources were not read in the PR body and the session note.** Do NOT merge any PR, do NOT run make extract/load, do NOT re-run the Pages workflow, never use --force or --admin.

## Branch and PR (parts 1-4)
The cycle date is the most recent 1st or 15th (so on the 3rd it is the 1st; on the 17th it is the 15th). One branch `claude/tournaments-<cycle date>` and one PR per cycle.
1. `git fetch origin`. If `origin/claude/tournaments-<cycle date>` exists and its PR is open: `git worktree add ../cc-tournaments-<cycle date>-pN -b claude/tournaments-<cycle date>-pN origin/claude/tournaments-<cycle date>` and push with `git push origin HEAD:claude/tournaments-<cycle date>`. Otherwise (Part 1 always, or an earlier part found nothing, or its PR was already merged): create the worktree from `origin/main` and push to a new branch `claude/tournaments-<today>`.
2. Use the main checkout's .venv. Copy courtconnect.duckdb from the main checkout for the build and delete the copy before committing. Seeds keep CRLF line endings.
3. Add events with the same columns as `transform/seeds/watch_events.csv`: verify dates and venue at the organizer or governing body; label inferred locations and tentative dates (`date_status`); https links only; `source_note` says what was read where; `verified_on` today. Update changed dates on existing rows. Do not add events from third-party aggregators without reading the organizer page; put those in `docs/tournament_sources.md` as leads. Any new place reference in `venue_actions.csv` must also be in `ci/fixtures/overture_places.csv`.
4. Checks: narrow dbt build (`--select stg_watch_events watch_events mart_watch_events`), `python ci/check_seed_evidence.py`, the full dbt build once, `python ingestion/export_app_data.py`, `python ci/check_export_fresh.py` (commit `app/data/venues.json` if it changed; on a conflict never hand-resolve it: `dbt build --full-refresh`, re-export). If you added venue_actions place references, also replay CI on the fixtures (move courtconnect.duckdb aside, `python ingestion/load_raw.py --data-dir ci/fixtures`, `dbt build`, restore).
5. Docs: in `docs/tournament_sources.md` add (Part 1) or extend (later parts) the section "Pass N (cycle date)" with a "Part k" sub-heading: sources read, added, changed, failed, "Last run: date". Write a NEW note `docs/sessions/<today>-tournament-part-N.md` (2-3 lines; do not edit CLAUDE.md or another session's note).
6. Commit (end the message with `Co-Authored-By: Claude Sonnet 5.5 <noreply@anthropic.com>`), push. If the cycle PR exists, append a "Part k" section to its body (`gh pr view --json body`, then `gh pr edit --body`); otherwise open it with `gh pr create`, body listing added/changed events by sport and failed sources, ending with `🤖 Generated with [Claude Code](https://claude.com/claude-code)`. If nothing new or changed is found and no cycle PR exists, open no PR, remove the worktree and say so in the final summary (still write the session note only if something was learned). Finish with a 5-line summary: sources read, added, PR link, failed sources, anything unread.

## PART 1: tennis, pickleball, ITF
- USTA SoCal playtennis search, USTA NorCal public sheet, USA Pickleball California list and Golden Tickets, PPA schedule; plus the Nevada equivalents where the source covers NV. Follow `docs/tournament_refresh.md` for each.
- ITF pro tour (CA + NV): the "Tennis + beach tennis, ITF pro tour" row of `docs/tournament_refresh.md`. itftennis.com shows a bot check to scripts, so do not curl/WebFetch it and do not work around it: find events by web search or the Wikipedia quarterly ITF pages, then open each tournament fact-sheet page singly in the built-in browser pane and read it as text. Copy facts only (name, dates, venue, link). In the December runs, look for the 2027 ITF World Tennis Tour calendar for CA + NV, the USTA 2027 Pro Circuit schedule and the 2027 ITF Beach Tennis calendar (none were published on 2026-10-17). Reuse existing venue pins; add to `manual_venues.csv` only if no dataset has the venue.

## PART 2: badminton, racquet sports on R2, table tennis, squash
- USA Badminton adult/junior schedules; R2 Sports state search for racquetball/squash/table tennis/padel/paddle tennis; Silicon Valley Open and US Squash; skyball.us/play; Nevada equivalents where covered.
- Table tennis: the Omnipong list https://omnipong.com/t-tourney.asp?e=0 plus the clubs' own tournament pages. The organizer page wins over Omnipong on venue and dates. The not-yet-added CA events are listed in `docs/tournament_pass_tt_badminton.md`: check their venues and add them when found. Read the full list, not just a keyword filter.
- Squash via Club Locker: follow the "Squash: Club Locker" section of `docs/tournament_refresh.md`. In the built-in browser pane (no screenshots), open clublocker.com's public tournament search, filter to United States and California (then Nevada), wait for the script-loaded list, read it as text. Never sign in; if the list needs a login or will not load, note it as a failed source. For each event dated today or later not already in `watch_events.csv` (match on name + start_date), open its public event page and read dates and venue. Row rules: event_key lowercase slug ending in the year, sport Squash, level pro/amateur/college/junior, watch_format `in_person_unconfirmed` unless ticketing is stated, date_status `dates_not_confirmed` if tentative, info_url https, source_note, verified_on today; label inferred venues in location_precision. No contact names or phones. Update changed dates on existing squash rows.

## PART 3: padel, beach tennis, lead rechecks
- The USA Padel calendar https://padelusa.org/calendar/ in the browser pane (4 pages of 20; calendar-only rows get date_status `dates_not_confirmed`; promote them when a registration or club page appears).
- Every organizer URL in `docs/beach_tennis_watch.md` (Beach Tennis Santa Monica, OLA, BT Cali Club, Beach Tennis Love; a league finals day is an event, the league season is not; recheck for December and 2027 dates from early November on). Hermosa/Manhattan/Santa Monica beach tennis tournaments.
- Rechecks: Bay Padel Dogpatch outdoor courts and Padel N9NE San Marcos opening (update `manual_venues.csv` / `venue_opening_status.csv` from the clubs' own pages when they open), the Southwest Regional of the USA Team League (nationalpadelleague.us).
- Padel lead recheck (owner 2026-10-21, `docs/padel_scan.md`): read each club's OWN public page as text (no owner logins). Clubs: the 3 light "Reported" pins in `transform/seeds/venue_opening_status.csv` (Ballers DTLA, King of Padel at West Harbor, WynPadel at the Westin Rancho Mirage) and every coming-soon / unconfirmed padel club in `transform/seeds/venue_leads.csv`. Only act on an official page: (a) confirms opening/date for a "Reported" pin -> set `venue_opening_status.csv` to `Opening soon` (keep verified_on + evidence); (b) club has opened -> delete its status row and update the venue in `manual_venues.csv` (courts, address, access), moving it out of `venue_leads.csv`; (c) page gone or club cancelled -> note under the PR's "needs owner decision", do not delete a pin or lead on thin evidence; (d) nothing official -> leave it. Never promote on a directory or press claim alone. List every club checked and the result (one line each) in the Pass section and the PR body.

## PART 4: Instagram sweep, social handles, player groups
- Instagram sweep of every provider=instagram account in `transform/seeds/venue_actions.csv` using `docs/instagram_sweep_snippet.js` under ADR 0009 and its 2026-10-19 amendment: public pages, logged out, never sign in, facts only, never store captions/images/counts/comments, read the post date and year, prefer the organizer's own page over a post; courts or accounts seen only in a post become leads in `venue_leads.csv`, not pins.
- Social handles for venues added since the last run.
- Player-group links (ADR 0009 amendment 2, item 6 of "Sources the scheduled run must also read" in `docs/tournament_refresh.md`): while doing the sweep and the new-venue site read, note any Meetup, WhatsApp (chat.whatsapp.com), Partiful or public Facebook group link a club publishes in its OWN bio or site and add it to `transform/seeds/player_groups.csv` (columns: group_key, name, platform, sports, area, url, published_at, evidence, verified_on; sports are sheet names split on ';'). Never join or request to join a group, never read members or messages, never store bio text, counts or images; a link found only by search is a lead in `docs/tournament_sources.md`, not a row. Then recheck every existing row: public Meetup/Partiful URLs must still load and the club page must still carry the link; refresh verified_on if so, remove the row if not and list removals under "needs owner decision". Do not export the seed or build a groups shelf (it waits for the owner).
