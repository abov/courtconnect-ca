# Scheduled runs: five parts (owner 2026-10-24; run as cloud routines since 2026-11-02, `docs/cloud_routines.md`)

The single 1st/15th run (tournaments for every sport + data refresh) stopped after one source on 2026-10-24: too big for one session at the low-usage settings. It is now five cloud routines on staggered crons on the 1st and 15th, all appending to ONE tournament PR per cycle, then the data refresh stacked on it. Each routine prompt (plus the cloud overrides in `docs/cloud_routines.md`) only says "read `docs/tournament_run_parts.md` from origin/main and do PART N"; the steps live here so they are versioned and reviewed.

| Part | Cloud routine (claude.ai/code/routines) | Cron (America/Los_Angeles) | Covers |
|------|---------|--------|--------|
| 1 | RacketConnect tournaments part 1 | 09:00 on the 1st and 15th | USTA SoCal/NorCal, USA Pickleball, PPA, ITF pro tour |
| 2 | RacketConnect tournaments part 2 | 10:30, gated on Part 1 | USA Badminton, R2 Sports, table tennis, Silicon Valley Open / US Squash, skyball, Club Locker squash |
| 3 | RacketConnect tournaments part 3 | 12:00, gated on Part 2 | USA Padel calendar, beach tennis organizers, padel rechecks and lead rechecks |
| 4 | RacketConnect tournaments part 4 | 13:30, gated on Part 3 | Instagram sweep, new-venue social handles, player-group links, new-court discovery for every sport |
| 5 | RacketConnect data refresh: part 5 | 15:00, gated on Part 4 | data refresh (`docs/refresh_agent.md`), stacked on the tournament PR |

**Schedule (owner 2026-10-27):** a scheduled run cannot start another scheduled run (the local tool refused: "Refusing to run a scheduled task from a scheduled-task run session"), so the parts are NOT chained. Each has its own cron on the 1st and 15th, spaced so they do not overlap, and each part is gated on the one before it.
- **Gate (first step of parts 2-5, before any work):** `git fetch origin`, then check that the previous part finished for this cycle: `docs/sessions/<today>-tournament-part-<N-1>.md` (or, for Part 5, Part 4's) exists on `origin/claude/tournaments-<cycle date>` (or on origin/main if that PR already merged), or the Pass section in `docs/tournament_sources.md` has a "Part <N-1>" sub-heading with "Last run: <today>". If a part found nothing and wrote no note, its Pass section line still counts. If the previous part is missing, wait up to 20 minutes (check every 5 with a short sleep), then stop with "PART N SKIPPED: Part <N-1> not done for <today>" and open nothing. A skipped part is run by hand later (Run now).
- No part starts another. Ignore any older instruction to start the next part.
- Part 1 is the only part that may create the cycle branch; later parts use the branch steps below.
- Never start a part that is already running (a second Run now is refused; that is fine, report it).

Spend: each part is estimated at $1-1.50; the $5 weekly / $10 monthly caps of `docs/refresh_agent.md` count Part 5 only, ADR 0019's $20 a month is the ceiling for all five. If the month's total runs past it, disable the Part 4 cron. Part 4 grew on 2026-11-02 (social series, open play, more states); if it cannot finish in one session, split the social-series bullet into its own Part (new routine) rather than reading fewer sources. Cloud routines need no machine on; a part that missed or was skipped is started by hand with Run now at claude.ai/code/routines (after the previous part finished).

## Rules for every part
Local manual runs work in `C:\dev\courtconnect-ca`; cloud runs use their clone and the overrides in their prompt (`docs/cloud_routines.md`). Commands run in Git Bash locally (dbt is `.venv/Scripts/dbt ... --project-dir transform --profiles-dir transform`, there is no make). Read CLAUDE.md first and follow it (never read .env, no Google Places data, public pages only, no owner logins, honesty over polish). Cost rules: no subagents, no screenshots, no extended web search, read pages as text, narrowest check first. **Do the whole part: read every source listed for it. Do not stop early to save usage; if you truly cannot finish, list exactly which sources were not read in the PR body and the session note.** Do NOT merge any PR, do NOT run make extract/load, do NOT re-run the Pages workflow, never use --force or --admin.

**Covered states (owner 2026-11-02).** Every "CA", "CA + NV" or "CA/NV" below means every state that is a key of `ingestion/regions.json` (CA, NV, OR, WA, HI and AZ by 2026-11-04; see the file, ADR 0028 and 0035): read the file, do not hardcode the list. For a state with no event history yet, the first cycle finds that state's governing-body equivalents (USTA section, USA Pickleball state list, USA Badminton / table tennis / squash / padel clubs, R2 and Omnipong rows) by one standard web search per sport, lists the sources it will reuse under that state in `docs/tournament_sources.md`, and reads them from the next part on. Events need a pin: reuse an existing venue, or follow the new-court rules in Part 4 step 3. Keep each state's rows in the same files (`watch_events.csv`, `r2_seen.csv`, `event_sources.csv`); no per-state seeds.

## Branch and PR (parts 1-4)
The cycle date is the date Part 1 started (the 1st or 15th; if you are started by hand on another day, today). One branch `claude/tournaments-<cycle date>` and one PR per cycle.
1. `git fetch origin`. If `origin/claude/tournaments-<cycle date>` exists and its PR is open: `git worktree add ../cc-tournaments-<cycle date>-pN -b claude/tournaments-<cycle date>-pN origin/claude/tournaments-<cycle date>` and push with `git push origin HEAD:claude/tournaments-<cycle date>`. Otherwise (Part 1 always, or an earlier part found nothing, or its PR was already merged): create the worktree from `origin/main` and push to a new branch `claude/tournaments-<today>`.
2. Use the main checkout's .venv. Copy courtconnect.duckdb from the main checkout for the build and delete the copy before committing. Seeds keep CRLF line endings.
3. Add events with the same columns as `transform/seeds/watch_events.csv`: verify dates and venue at the organizer or governing body; label inferred locations and tentative dates (`date_status`); https links only; `source_note` says what was read where; `verified_on` today. Update changed dates on existing rows. When an existing upcoming row is still correct at its source (the page you read this run shows the same dates), set its `verified_on` to today: the "oldest upcoming-event check" SLA (14 days) counts that column, and a refresh PR fails the scorecard gate (2026-10-25: five PPA/BNP rows aged to 16 days) if rows are read but not re-dated. Do not add events from third-party aggregators without reading the organizer page; put those in `docs/tournament_sources.md` as leads. Any new place reference in `venue_actions.csv` must also be in `ci/fixtures/overture_places.csv`.
4. Checks: narrow dbt build (`--select stg_watch_events watch_events mart_watch_events`), `python ci/check_seed_evidence.py`, the full dbt build once, `python ingestion/export_app_data.py`, `python ci/check_export_fresh.py` (commit `app/data/venues.json` if it changed; on a conflict never hand-resolve it: `dbt build --full-refresh`, re-export). If you added venue_actions place references, also replay CI on the fixtures (move courtconnect.duckdb aside, `python ingestion/load_raw.py --data-dir ci/fixtures`, `dbt build`, restore).
5. Docs: in `docs/tournament_sources.md` add (Part 1) or extend (later parts) the section "Pass N (cycle date)" with a "Part k" sub-heading: sources read, added, changed, failed, "Last run: date". Write a NEW note `docs/sessions/<today>-tournament-part-N.md` (2-3 lines; do not edit CLAUDE.md or another session's note).
6. Commit (end the message with `Co-Authored-By: Claude Sonnet 5.5 <noreply@anthropic.com>`), push. If the cycle PR exists, append a "Part k" section to its body (`gh pr view --json body`, then `gh pr edit --body`); otherwise open it with `gh pr create`, body listing added/changed events by sport and failed sources, ending with `🤖 Generated with [Claude Code](https://claude.com/claude-code)`. If nothing new or changed is found and no cycle PR exists, open no PR, remove the worktree and say so in the final summary (still write the session note only if something was learned). Finish with a 5-line summary: sources read, added, PR link, failed sources, anything unread.
